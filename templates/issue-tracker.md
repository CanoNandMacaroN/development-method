# 项目任务对接模板

生成到 `docs/agents/issue-tracker.md`。本文件只绑定项目位置和操作，不复制[通用开发流程](../handbook/principles-and-flow.md)。生成后所有链接按目标位置改写。

| 职责 | 空项目默认 | 项目应填写的实际内容 |
|---|---|---|
| 有效需求 | `docs/PRODUCT.md` | 已确认规格位置与详细功能规格的拆分方式 |
| 任务范围与依赖 | `docs/BACKLOG.md` | 唯一任务列表、编号约定和当前阶段 |
| 当前领取与进度 | `docs/STATUS.md` | 当前任务、负责人、代码版本、工作副本、范围及等待条件的位置 |
| 某次执行证据 | `docs/tasks/` 按任务编号记录 | 使用任务记录模板的位置；尚未执行时注明尚无记录 |
| 工程取舍 | `docs/decisions/` | 现行决定及引用方式；需要时创建记录 |
| 新想法与请求 | 同一 backlog 的后续候选 | 分流字段与原需求、既有任务的关联方式 |

把技能操作逐项映射：读取任务、写规格、拆任务、建立依赖、领取、补充证据、完成或退回、追加有日期的答复。映射只指向上表中的权威，不建立平行队列。新任务先核对依赖及具体授权，完成状态来自验收证据。

`wayfinder` 被采用时，明确决定图保存在何处，以及问题编号、依赖、领取、回答、替代关系和汇总链接分别怎样记录；复用现有决定与状态位置。尚未需要该能力时注明按需建立，不预造研究队列。

默认本地文件操作。若项目已有外部 tracker，填平台、目标、字段映射与已授权操作范围；远端只保存目标标识，不写凭据。外部 PR/MR 作为请求来源默认关闭。
