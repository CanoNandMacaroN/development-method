# Matt 技能全集：介绍与项目用法

规范版本：`0.1.0`。这里完整介绍**此前审阅的 39 项 Matt 技能**，作为开发者可安装使用的基础能力；这不是对上游当前技能总数的声明。技能由开发者自己安装和更新，项目只保留怎样配合本项目开发的方法细则。会话目录没有显示某项技能，不代表它未安装或可以从说明中省略。

公开来源是 [mattpocock/skills](https://github.com/mattpocock/skills)。[机器可读说明](../registry/matt-skills.json)列出用途、触发条件、协作分工和项目适配规则，供人和代理按任务查阅。本表描述此前审阅的内容；实际使用时读取开发者已安装版本。具体安装命令见[开发者准备](developer-setup.md)。

## 按原名称使用已安装技能

来源分为 `engineering` 21 项、`productivity` 7 项、`misc` 4 项、`in-progress` 7 项。课程、写作、Claude 专用和进行中能力全部介绍，按合适场景使用。

调用前先读项目的 `skill-usage` 使用细则，确认规则、路径、检查命令和权限，再读取开发者已安装的相应技能。沿用它的原入口名称和跨技能引用，不建立重命名入口。项目已确认决定与技能建议有差异时，将差异写在使用细则中，安装文件保持原状。

部分技能声明 `disable-model-invocation: true` 或 `allow_implicit_invocation: false`，因此只作显式入口。说明表保留这一事实，实际调用方式以安装版本及当前宿主为准；项目不修改这些标记，也不在初始化时执行全部技能。通用规范版本可以固定，技能的安装和升级由开发者管理。

## 用 setup 接好三份项目文档

项目初始化采用开发者已安装的 `setup-matt-pocock-skills` 配置三个接缝。已有项目可以让接缝指向现行资料，避免重复维护权威内容。

| 默认接缝 | 初始化时写清什么 |
|---|---|
| `docs/agents/issue-tracker.md` | 任务和规格在哪，怎样读写、领取、设置依赖及关闭；本地、GitHub、GitLab 和其他跟踪器均可适配。没有远端授权时可以使用本地记录 |
| `docs/agents/domain.md` | 现行词汇、相关决定在哪，哪些情况下读取；沿用单上下文或实际存在的多上下文布局 |
| `docs/agents/triage-labels.md` | 五种分流状态和分类在本项目怎样表达；沿用已有名称，避免重复标签。记录映射不等于创建远端标签 |

先读现状并继承已确认选择，只有真实分歧才询问。外部 PR 是否作为待分流请求，默认保持关闭，除非项目明确选择开启。代理入口按当前宿主实际读取机制链接这三份接缝。项目只记录该技能需要的资料绑定与例外；通用使用方法继承本包，不另造技能安装器。

## 如何组合使用

从想法到开发，可以由 `ask-matt` 帮用户选择路线：项目访谈用 `grill-with-docs`，关键不确定性用 `research` 或 `prototype`，确认后用 `to-spec` 和 `to-tickets` 形成规格及任务，再选择 `implement` 或 `implement-spec`。这是一条可按任务进入的路线，不要求每次修复都从第一步开始。

`tdd` 提供行为测试方法，项目使用细则按已确认行为与授权规则 由 AI 自主选择局部测试边界；未明确的产品行为和授权范围才需要用户决定。`code-review` 做规范、规格两条检查，`check` 可补充实际风险与开发交付证据。规划、访谈与实现共用已确认决定，避免重复批准。

具体库、API 和 CLI 用法通过项目 ctx7 入口先定位资料再查询，源码定位按项目 CodeGraph 索引状态选择入口，执行方式见[工具与技能](tools-and-skills.md)。其他已安装技能也可按任务读取；存在重叠时明确分工，不删掉 Matt 技能说明。

所有委派共享主代理之外最多两名并行子代理的额度。需要三个以上方案时分批完成；模型未另行约定时继承当前模型。文件写入、安装、远端评论、账户设置和后台代理启动分别检查现有授权，技能被列入说明不会自动扩大这些范围。

## 逐项用途与使用细则

下表列出实际技能名称和项目需要明确的事项。完整差异及动作前提保存在机器可读说明中。文中的技能模板和参考文件由已安装技能提供，按实际安装位置读取；项目路径则沿现有权威资料设置。

### 工程技能 · `engineering`

| 原技能名称 | 用途与触发 | 与相关能力分工 | 项目位置与动作前提 |
|---|---|---|---|
| `ask-matt` | 找到适合当前工作的技能路线。用户询问该用哪个技能，或需要选择一条开发路线。 | 作为总导航；grilling 澄清决定，think 可整理方案，不能再平行启动第二套访谈。 | 保留完整路线和独立技能入口，不按会话可见目录裁剪。项目的规范、规格、任务跟踪与上下文接续入口；宿主实际支持的清理上下文、摘要和委派能力。本技能主要给出路由；被路由技能的写入、联网和启动动作分别检查授权。 |
| `code-review` | 分别审查规范符合性和需求符合性。一个可交付成果完成自查，或用户要求检查分支、PR 或某个基线以来的修改。 | 保留两轴结果；check 补充实际风险和交付证据，同一改动只形成一份完整审查结论。 | 使用 setup 生成的任务跟踪接缝；不得因其缺失而删掉该依赖。docs/agents/issue-tracker.md；现行规格、编码约定、固定比较基线、未提交及未跟踪文件范围。审查默认只读；修复、远端评论、合并和发布使用各自已授予的范围。 |
| `codebase-design` | 设计小而清楚的接口，将相关行为集中到可验证的模块。接口、依赖、测试边界或架构改进需要具体设计。 | domain-modeling 管领域含义；本技能管模块形状；improve-codebase-architecture 负责寻找候选。 | 保留原架构词汇并解释中文含义，不覆盖项目领域术语。项目领域词汇和架构决定；受影响模块、接口和行为检查。设计讨论不自动授权重构；删除测试和改变接口限于已选择的工作范围。 |
| `diagnosing-bugs` | 建立能捕获原问题的失败检查，缩小复现并检验根因。难以直接定位、间歇发生或性能退化的缺陷。 | 与 hunt 共用症状、假设和证据记录；疑难分支采用本技能，不重复跑完整流程。 | 本地观察、样例和命令由 AI 调查，缺事实不向用户重问可查内容。领域词汇和相关决定；复现样例、测试入口、临时诊断目录；scripts/hitl-loop.template.sh 中的实际步骤。压力测试、临时日志、服务启动和真实环境探针先检查目标与影响；不扩展到未授权正式环境。 |
| `domain-modeling` | 统一领域概念和关系，保留重要设计取舍。出现含义冲突、需要命名领域概念或记录重要决定。 | grill-with-docs 负责访谈组合；codebase-design 处理架构词汇；teach 的学习词汇不覆盖产品词汇。 | 保留单/多上下文能力，沿已有权威目录薄映射，不制造第二份词汇表。docs/agents/domain.md；GLOSSARY.md 或 GLOSSARY-MAP.md 映射；项目现有决定记录目录。更新词汇和决定是项目文档写入；原始用户证据保留，不把建议写成已批准。 |
| `grill-with-docs` | 访谈时同步维护领域词汇和重要决定。用户在项目中明确需要 Grill 并形成可追溯文档。 | 组合 grilling 与 domain-modeling；与 think 共享确认结果，不重复审批。 | 保留原组合能力，记录位置由 setup 接缝确定。docs/agents/domain.md；项目现行决定和词汇位置。会写领域文档；仅将已形成的决定记为确认。 |
| `implement` | 按规格或工单实现一项工作并审查。用户授权实现一项范围明确的功能或修复。 | tdd 负责行为验证，code-review 负责完成后的独立审查；implement-spec 处理多任务图。 | 默认测试先行，AI 自主选择局部测试边界。当前规格与任务记录；项目检查命令、短期任务分支和提交约定。修改代码、运行检查、可能提交；不从实现授权推导远端推送或发布。 |
| `improve-codebase-architecture` | 依据真实修改热点寻找架构改进候选并展示理由。用户要求评估架构可理解性、可测试性或选择改进方向。 | 本技能找候选；codebase-design 设计选定接口；grilling 澄清重要取舍；health 不替代源码分析。 | 报告原用系统临时目录和 CDN；按项目写入边界、网络政策使用允许目录与可用本地渲染资源。领域与架构文档；允许的 HTML 报告目录和预览入口；外部 CDN 资源政策。写报告、可能打开预览和加载 CDN；架构改动另依用户所选范围，不自动大规模重构。 |
| `prototype` | 用可操作的临时代码回答一个状态或界面设计问题。文字讨论不能判断行为或界面，需要探索性原型。 | 研究给资料，grilling 做取舍，prototype 提供可体验证据；正式实现回到 implement 和 tdd。 | 先写问题和投入上限，明确探索结论与功能交付不同。LOGIC.md 或 UI.md 对应的分支；项目原型位置、运行入口、样例数据与保存分支。生成文件、可能启动预览、建立分支或提交；保留证据前不随意删除用户修改。 |
| `research` | 调查一手资料并保存带来源的结论。需要文档事实、外部资料或后台阅读来支持决定。 | 具体 API 语法先走 ctx7 入口；本技能处理跨来源问题，结果供 Grill、规格或实现使用。 | 需要委派时计入两名并发额度，满额则等待或主代理调查。项目研究材料目录；允许发送到文档服务的查询内容；当前子代理额度。可能联网查询并写研究文件；查询不包含秘密或未授权私有源码。 |
| `resolving-merge-conflicts` | 理解冲突两边意图，形成一致结果并验证。存在需要处理的合并或变基冲突。 | 审查判断结果，Git 集成规则决定目标与提交；不借冲突处理加入新功能。 | 项目使用细则说明 always resolve/never abort 的适用边界：无法安全保留意图时说明冲突，是否中止按任务目标和授权判断。冲突状态、两侧提交意图和目标分支；项目检查及暂存提交范围。改冲突文件、暂存、合并或变基继续会改 Git 状态；公共历史重写不由本技能授权。 |
| `setup-matt-pocock-skills` | 建立其余 Matt 工程技能依赖的项目接缝。单项目首次初始化，或明确更换任务跟踪、领域布局与标签约定。 | 项目初始化采用开发者已安装的这个技能配置三份接缝，不另造技能安装器；通用手册说明如何配合项目现状。 | 三份文件保留为默认接缝；已有权威资料时写薄映射和操作约定，不复制另一份需求、状态或词汇。docs/agents/issue-tracker.md；docs/agents/domain.md；docs/agents/triage-labels.md；当前宿主读取的 AGENTS.md 或 CLAUDE.md 入口。写项目接缝和代理入口；不会仅因写了使用说明就创建远端标签、issue 或账户配置。 |
| `tdd` | 通过真实接口逐个验证行为，避免跟着实现重复计算预期值。行为明确的功能或缺陷默认触发，探索原型与简单修改按已定例外。 | implement 和 implement-spec 使用它；diagnosing-bugs 先建立问题复现；code-review 独立检查结果。 | 项目使用细则说明本方法与逐测试边界确认的差异：AI 自主选择局部测试和技术手段，未定行为或越权范围才问用户；不修改开发者安装的技能。项目实际测试入口、领域词汇、接口及样例；tests.md 与 mocking.md。写测试与实现、运行进程和样例；真实数据、外部 API 和费用不由测试先行自动授权。 |
| `to-spec` | 把已讨论的需求整理成可实现和验收的规格。用户要求把现有对话或决定形成规格。 | 承接 Grill 和原型，to-tickets 再拆分；不把规格整理变成重新访谈。 | 按已确认行为与授权规则 自主说明测试边界，项目使用细则记录与技能逐测试批准要求的差异，已安装技能保持原状。docs/agents/issue-tracker.md；docs/agents/triage-labels.md；领域词汇、需求权威及验收入口。写规格、可能创建 issue 和标签；未授权外部写入时先形成可审阅本地稿。 |
| `to-tickets` | 把规格拆成可体验或验证的小任务，标明真实依赖。规格需要跨任务实现，或用户要求拆票。 | 规格承载行为，任务只写该段成果与依赖；to-tickets 产物已经明确，无须再经过 triage。 | 沿用已确认拆分尺度和人工反馈节点，只对改变范围或依赖的关键取舍提问。docs/agents/issue-tracker.md；docs/agents/triage-labels.md；一票一文件或远端 issue 及原生依赖操作。创建任务文件或远端 issue/子 issue/依赖和标签；不关闭父 issue，不推导公开写入授权。 |
| `triage` | 核实外来需求、缺陷及选定 PR，形成可执行任务或清楚的处理结论。用户要求整理收到的未澄清请求，或改变指定请求状态。 | setup 提供跟踪器和标签；diagnosing-bugs 复现；grilling 补行为；code-review 审查已有差异。 | 按实际请求范围区别只读汇总、准备建议和外部评论/关票，不把调用技能当作所有写入授权。docs/agents/issue-tracker.md；docs/agents/triage-labels.md；AGENT-BRIEF.md 与 OUT-OF-SCOPE.md；项目拒绝决定目录及有效规格。可能运行复现、写 brief、改变标签、评论和关票；外发内容保持 AI 来源说明，敏感内容脱敏。 |
| `wayfinder` | 把超出一轮上下文的大型未知工作整理成相互依赖的决定任务。用户要求规划大范围且路线尚不清楚的工作。 | grilling 处理一轮问题；本技能维护跨轮决定图，明确后再经 to-spec/to-tickets 进入实现。 | 保留决定图、模糊区域和范围外区分，不强制对已清楚的小任务建立地图。docs/agents/issue-tracker.md 中的 Wayfinding operations；地图、决定任务、领取和阻塞状态；研究或原型证据位置。可创建、领取、评论、关闭或调整决定任务；实际远端写入、服务注册和数据移动按具体授权。 |
| `wizard` | 把只能由人完成的设置写成逐步交互引导。用户需要输入秘密、账户确认或人工界面操作，且 AI 不能独立完成该步骤。 | setup-matt-pocock-skills 配置方法接缝；本技能解决人工操作，不接管普通可自动执行的工作。 | 静态审阅模板的浏览器打开、mktemp、环境文件替换和 gh secret/variable 写入，按项目边界适配后再生成。约定脚本和临时文件目录；环境文件、CI 字段与目标仓库；template.sh 实际帮助函数及运行环境。生成脚本后人工运行可能打开浏览器、改环境文件、写远端 CI 配置；这些步骤在执行前明确目标和授权。 |
| `implement-spec` | 沿依赖任务图组织多个实现并集成完整规格。用户授权完成具有关联工单的整份规格。 | implement 处理单任务，tdd 提供实现纪律，code-review 审查集成结果；宿主适配承担实际调度。 | 最多同时两名子代理，探索、实现、集成和审查共享额度，不能按原文 maximum concurrency 无限扩张。docs/agents/issue-tracker.md；规格、依赖图、集成分支及隔离工作副本；项目允许的研究目录和宿主委派入口。建分支/worktree、启动代理、合并、可能创建 PR 和修改任务状态；自动清理不能删除未保存工作。 |
| `pr` | 以变化、前后证据和影响说明写清 PR 正文。需要准备或更新 PR 说明。 | code-review/check 提供发现及验证，write 负责清楚表达；本技能组织审阅材料。 | 复用技能建议的表达方式时尊重上游署名，采用能说明变化的最小图示；简单变化无需为模板制造图表或额外章节。仓库 PR 模板、领域词汇、实际差异和证据链接。写正文不等于创建、更新或发布远端 PR；外部写入需要对应授权。 |
| `retro` | 根据实际开发过程改进导航、检查和代理规则。用户要求复盘指定任务或当前会话。 | health 盘点工具配置，check 审代码，retro 从过程证据寻找下一轮改进。 | 只读取明确范围内的会话，不为复盘扫描所有私人历史。当前任务或用户明确指定的会话证据；项目已有检查与代理文档；writing-for-agents 规则。默认提出改进；实施规则、hook 或访问权限变化限于明确授权，不每次复盘都自动扩建环境。 |

### 协作、沟通与学习技能 · `productivity`

| 原技能名称 | 用途与触发 | 与相关能力分工 | 项目位置与动作前提 |
|---|---|---|---|
| `grill-me` | 无持久领域文档的访谈入口。用户显式要求此访谈方式，或讨论没有项目文档的个人想法。 | 只转入 grilling；有项目且需要随问随记时使用 grill-with-docs。 | 保留这个短入口，不因内容简单而移除。当前语言和问题编号；已确认决定。仅对话；事实调查和委派遵守现有范围与并发上限。 |
| `grilling` | 按依赖关系逐轮明确目标、约束和决定。计划、设计或想法仍存在影响执行的真实取舍。 | grill-me 和 grill-with-docs 是入口，wayfinder 与 triage 按需使用；同一问题不多轮重复确认。 | 环境事实由 AI 查明，决策留给用户。已确认决定及当前讨论范围；本轮问题编号和用户阅读语言。访谈本身不授权安装、发布或改变外部状态。 |

| `to-questionnaire` | 为持有缺失知识的人准备可以填写的问卷。问题依赖其他人的知识，用户要求先准备问卷。 | grilling 询问当前用户的决定；本技能只补收件人、目的和问题缺口；write 负责语言质量。 | 已知受众和目标直接继承，查询资料可以解决的问题由 AI 先查。约定问卷目录、受众、用途、时间要求及语言。生成 Markdown 问卷；发送消息、邮件或邀请另需用户授权。 |
| `wait-what` | 补足背景，用用户理解的语言重新解释上一段内容。用户表示没听懂、跟不上或要求换个方式说明。 | write 改善表达；teach 是另一个系统学习场景；本技能不改变开发目标。 | 已安装技能要求简化技术英语；项目为中文时用同等清楚的中文，不强制切换英语。当前语言、项目领域词汇和用户已知背景。只重新说明；不会因解释请求自动改文件或暂停原任务。 |
| `writing-for-agents` | 让技能、项目入口和按需文档能稳定引导代理。编写或修改代理消费的规范、技能和导航。 | write 面向人的语言质量；本技能管触发、层次和完成条件；仅在用户要求编写自定义技能时再使用 skill-creator。 | 调用前先读项目 skill-usage 细则，再读开发者安装的技能；使用原入口名及其显式或隐式调用方式，项目不改标记。项目短入口、权威正文与引用结构；SKILL-MECHANICS.md 及宿主实际技能发现机制。当前范围只改项目文档和使用细则；修改开发者安装的技能或全局配置须有对应授权。 |
