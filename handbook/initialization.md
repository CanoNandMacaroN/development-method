# 初始化：建立项目的开发入口与技能使用细则

规范版本：`0.1.0`。初始化让人和代理找到有效需求、正确环境、唯一工作入口，以及技能怎样配合这些资料。技能由开发者自行安装；项目初始化只建立和整理开发文档，不安装或修改技能。首次使用从[启动入口](../START-HERE.md)开始，其中已确定空项目的默认文档结构和本地任务组织方式。Grill 仅补充项目细节，通用开发方法直接继承。

[开发者环境准备](developer-setup.md)给出安装与核对命令；[Matt 技能全集](matt-skills.md)介绍全部 39 项能力。已有项目保留产品决定、实现、任务与证据，以薄映射接入当前方法，不重新建仓。

## 1. 只读核对现状

新项目核对目标、约束、原型与可复用组件。已有项目先读入口、现行需求、状态和近期证据，再核对代码、分支、未提交修改、检查入口与环境。保留已有工作，不靠清空目录或重置历史取得干净状态。

本步收集：

- 真实项目根、现有 `AGENTS.md` 或 `CLAUDE.md`、采用规范和项目覆盖。
- 任务、规格、当前状态、术语与架构决定的位置，特别是既有 backlog。
- 项目类型、代码与测试数据、真实验证环境、包执行器及缓存等边界。
- 当前所需技能是否已安装、是否可被宿主调用，版本信息是否能核对。
- 项目根是否存在 `.codegraph/`，Context7 的项目入口及实际状态。

技能目录完整保留 39 项介绍，项目记录当前真正具备哪些能力。缺项时报告技能原名、所需步骤和开发者安装命令，等待开发者处理；其余独立资料整理可以继续。没有 CodeGraph 索引时标明未索引，直接使用文件检索；不为完成初始化创建索引。

## 2. 固定方法版本，明确项目差异

项目固定通用规范版本，升级时查看方法变化和项目覆盖。开发者安装的技能、CLI、MCP 版本另行记录，方法版本与安装环境不混为一项。

现行目标与关键架构先明确，当前小阶段写到可实现、可验证。流程按项目性质使用，省略步骤说明理由。已有更严格的环境和授权边界继续生效；项目依赖与产物独立，运行时和缓存按约定复用。

形成一份具体适配清单：哪些现有文件保持权威、需要补什么接缝、哪些引用要更新、哪些环境尚未验证。只对无法从现状确定且影响选择的问题询问；已确认的产品行为和开发偏好直接沿用。

## 3. 用已安装的 setup 技能接通三份资料

使用开发者已经安装的 `setup-matt-pocock-skills`，读取它的说明及本地任务、领域、分类模板，把当前事实落实到下列文件。技能缺失时，可先按本包的[任务](../templates/issue-tracker.md)、[领域](../templates/domain.md)和[分流](../templates/triage-labels.md)模板形成文档，注明尚未通过原技能接入，提供开发者安装入口。使用完整原技能名称，不创建项目别名。

| 文件 | 写清什么 | 已有项目怎样接入 |
|---|---|---|
| `docs/agents/issue-tracker.md` | 规格和任务在哪，怎样读取、创建、领取、设置依赖、更新及关闭 | 指向现行 backlog、规格与状态页，逐个映射技能操作 |
| `docs/agents/domain.md` | 领域词汇和相关架构决定在哪，何时阅读、怎样处理冲突 | 引用已有词汇表与决定目录，不复制第二份正文 |
| `docs/agents/triage-labels.md` | 五种分类角色对应哪些本地状态或远端标签 | 沿用现有用语，注册映射不等于创建远端标签 |

本地模板的 `.scratch/<feature>/` 是可用约定，不是所有项目必须新增的目录。已有 backlog 时，`to-spec`、`to-tickets`、`triage` 与 `wayfinder` 都通过同一适配工作。研究问题、领取、依赖和回答写回指定权威，不能平行出现两套可执行队列。

五种角色是 `needs-triage`、`needs-info`、`ready-for-agent`、`ready-for-human`、`wontfix`。它们描述任务需要什么处理，不替代验收结果。相关技能尚不可用时如实标明，保留项目已经确定的用语。

setup 中的提问依照现行事实和授权处理，已确定的选择不再重复确认。默认路径、远端平台或 PR 入口都要对应本项目的真实选择，调用技能本身不扩大外部写入权限。

## 4. 写项目使用入口与工具规则

项目保留这些文档职责，详细内容可以沿用现有材料：

| 产物 | 负责什么 |
|---|---|
| 项目指南 | 目标、阅读顺序、采用的规范版本与适配入口 |
| `docs/agents/skill-usage.md` | 引用通用协作规则，填写本项目资料绑定与例外 |
| `docs/agents/tool-adapters.md` | Context7、CodeGraph、Herdr 及其他工具的实际命令、环境参数、状态和验证 |
| setup 的三份资料 | 任务权威、领域记录和分类角色的操作接缝 |
| 现有代理入口 | 简短指向上述材料及当前任务，不复制整本手册 |
| 现行任务证据 | 适配了什么、检查了什么、哪些仍未验证 |

[技能使用细则模板](../templates/project-skill-policy.md)用于形成 `skill-usage.md`，[工具适配模板](../templates/tool-adapters.md)用于填写实际环境。工具配合顺序、通用细则、完整介绍和安装命令链接回方法包；项目不再复制这些规则，只填具体位置、命令、环境和例外。

按当前宿主沿用 `AGENTS.md` 或 `CLAUDE.md`，只更新相关入口，保留已有其他规则。有多个入口时指向同一权威。短入口至少说明：

- 工程任务先读 `skill-usage.md`，再读取已安装技能及必要资源。
- 具体库、API、CLI 或服务用法优先走项目 Context7 CLI，先 `library` 后 `docs`，每问题最多三次。
- 理解代码前确认真实项目根；有 `.codegraph/` 时先 explore，无索引普通检索，索引由用户决定。
- 任务、术语和分类分别使用 setup 指定的权威位置。

## 5. 检查文档能否指导真实动作

检查链接能找到现行材料，任务操作能回到同一队列，规范版本与项目差异可理解，安装命令入口可找到。核对具体工具配置与实际环境，不能只把默认示例写进去就宣称可用。

| 检查 | 通过能说明什么 |
|---|---|
| 入口、链接与权威映射 | 人和代理能找到本项目有效资料 |
| 已安装技能与宿主发现 | 当次环境能找到相应技能与调用入口 |
| Context7 或其他工具的最小调用 | 指定目标与环境中的入口当次可用 |
| CodeGraph 根与索引探测 | 本项目应走索引查询还是普通检索；缺索引并非初始化失败 |
| 一次实际开发演练 | 选定使用过程从需求到验证确实可执行 |

配额、网络、权限和未执行项分别报告。没有索引就不调用 CodeGraph 查询；未获得允许的 Herdr 上下文就不访问会话。文档检查、技能可见、工具调用和完整开发流程是不同层次的证据。

## 6. 按授权进入第一个小任务

只有初始化授权时，交付起步文档与第一个可执行任务，实际开发演练记为未实施。已获实现授权时，选择行为清楚、可独立验证的功能或修复，从项目入口读取需求，通过 `skill-usage.md` 选择所需技能，确认测试失败，再实现、验证、独立审查并更新唯一状态。每轮只使用匹配的能力，不要求把完整目录跑一遍。

演练尽早触及真实环境；缺条件时继续独立部分，说明尚未验证的环节。只证明技术可行性时记为探索。远端同步、发布和数据删除仍按具体授权处理。

结束后据实际问题修正使用细则，保留规范版本、项目差异和验证范围。已有项目注明原权威怎样接入，不重开产品决定。以后方法升级与开发者环境升级分别评估，再验证受影响的开发过程。
