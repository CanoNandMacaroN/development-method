# 工具与技能的通用协作规则

规范版本：`0.1.0`。本手册介绍全部 39 项 Matt 技能及本机补充能力。技能由开发者自行安装。工具的分工、调用顺序和通用使用细则统一在本包维护；项目层只保存资料位置、命令、实际环境、可用状态和有理由的例外。每次任务按触发条件读取所需技能，不要求依次调用全部入口。

安装与核对命令统一见[开发者环境准备](developer-setup.md)。缺少某项技能时，报告完整名称、影响的步骤和该说明中的安装命令，交给开发者执行；项目初始化不代装，也不改开发者已有技能。

## 通用方法与安装环境分别记录

项目固定采用一个通用规范版本，按版本差异升级。这是项目怎样开发的约定。技能、CLI 和 MCP 则记录开发者实际使用的来源、可取得的版本信息、宿主及检查日期；不能因为手册版本固定，就宣称安装环境也被固定了。

项目的使用入口为 `docs/agents/skill-usage.md`。它链接本页的通用规则，只填写当前需求和任务记录的位置及项目例外。详细工具入口在 `docs/agents/tool-adapters.md`。技能资源从已安装位置读取，项目文档链接使用方法和必要规则，不保存另一套技能实现。

开发者更新安装环境后，实际行为可能变化。下一次使用时核对相关技能说明和项目规则；发现差异就说明影响并调整使用细则，已有任务结果仍按当时环境解释。

## 一项工作怎样把这些能力连起来

1. **确定行为**：读取项目规格和任务；有真实取舍时用 Grill，已有决定直接沿用。通过 `to-spec`、`to-tickets` 将结果写回项目指定位置。
2. **取得事实**：具体外部技术用法通过 Context7 查当前资料；已有代码的结构与调用关系通过 CodeGraph 定位。前者回答“这个库现在怎样用”，后者回答“本项目怎样实现”；两者各按下文前提使用。
3. **安排工作**：需要并行实现时，优先通过可用的 Herdr 管理独立工作副本、终端和代理；单个简单任务沿用当前环境。并行组织不会改变任务权威和验收条件。
4. **实现与验证**：按任务使用实现、TDD 或诊断技能，运行项目记录的检查命令。发现新的产品取舍时回到决定记录，日常实现选择由 AI 完成。
5. **审查与接续**：审查固定候选及其规格，主代理集成后验证组合结果，将结果和未完成条件写回唯一状态与任务证据。

这是条件化流程，不是每项任务都必须调用四类工具。文档修改通常不需要 CodeGraph；未索引项目采用普通源码检索；没有并行任务时无需启动 Herdr 工作副本。缺少能力按下文记录影响并使用能提供同类证据的入口。

## 本机其他能力怎样补充

`think` 可以整理计划，`find-docs` 提供资料查询方法，`hunt` 可与故障诊断共享复现和假设，`check` 补充交付检查，`write` 帮助人读文档。界面、浏览器、文档制品及其他能力按任务使用。说明它补充哪个步骤和依赖什么，不因用途重叠而删去 Matt 目录中的介绍或入口。

技能描述流程，MCP 或 CLI 执行动作；一个流程可能有多个执行入口。已安装不代表当前会话可调用，配置存在也不代表已验证。开发者负责安装，通用包规定配合方式，项目记录实际入口与边界。

## Context7：先解析资料，再查具体问题


涉及库、框架、SDK、API、CLI 或云服务的具体用法时，优先通过 Context7 CLI 核对。一般业务逻辑、普通代码审查、从头写脚本和不涉及具体 API 的重构，不因此强制查询。

实际入口写在 `docs/agents/tool-adapters.md`，包括项目 runner、工作目录、缓存与配置落点。查询通过该入口传递给 `ctx7`，不能直接绕过项目包管理约束。

1. 用官方名称调用 `library`，查询一个具体问题，取得有效资料 ID；用户已提供合法 `/org/project` 或版本 ID 时可直接使用。
2. 按名称与问题相关性、来源信誉、资料覆盖和评分选择结果。指定版本使用返回的版本 ID，不自行拼接。
3. 调用 `docs` 查询单一概念；多个概念分别查询，讨论它们的交互时才组合。
4. 依据返回资料回答，说明实际版本与仍未核对的部分。

每个问题最多三次查询，换入口不重置预算。查询不包含凭据、私人正文或私有源码。CLI 的下载、缓存和登录配置服从项目约定；`find-docs` 中可选的全局安装方式不能覆盖项目环境边界。

配额失败如实说明，并建议通过项目允许的入口登录或配置 `CONTEXT7_API_KEY`，不代替用户登录。网络失败按实际权限处理：允许在默认沙箱外执行时使用相应入口；已经处于该环境或不允许提权时，报告实际限制，不重复无效重试或声称已经绕过限制。

CLI 不可用时，可以使用当前可调用、已获准且满足同一目的的 Context7 MCP 替代，保留“解析库 ID，再查询文档”的顺序。记录替代原因、工具、资料 ID、版本覆盖和结果限制；不假设两者的格式、索引版本与额度完全相同。MCP 成功不能写成 CLI 成功，未取得需要的资料时明确尚未核对。

## CodeGraph：先看项目是否已经索引

需要理解或定位代码时，先确认本次工作的真实项目根，再探测其中是否存在 `.codegraph/`。存在索引时优先使用 `codegraph_explore`；MCP 明确传入本项目的 `projectPath`，CLI 则在对应项目根运行 `codegraph explore`。定位后核对当前源码。

没有索引时记录“未索引”，直接使用普通文件检索和阅读。是否建立索引由用户决定，初始化不会为了补齐工具清单运行索引或查询，也不会把工具安装写成项目已启用。

索引存在但查询失败或内容过期时，记录实际状态，必要时通过普通检索核对源码。更换工作副本后重新确认根与索引归属，不沿用其他项目或副本的 `projectPath`。

## 通用执行细则

以下是每个采用项目直接继承的规则。项目的 `docs/agents/skill-usage.md` 引用本节，仅对实际差异记录理由和验证办法；不逐项复制，也不改已安装的技能正文。

- 已确认目标和授权继续有效，规划与 Grill 共用决定记录，避免重复确认。
- AI 自主选择已定行为的测试边界；局部重构可以在测试保护下随任务进行。
- 工单发布、领取和更新使用 `issue-tracker.md` 指定的唯一权威，不因默认路径创建第二队列。
- 术语与架构决定通过 `domain.md` 找原位置，不复制第二套正文。
- 审查共用固定候选与证据；并发、写入隔离和集成遵守项目约定。
- 安装、网络、Git、外部写入和发布按具体授权处理，不继承自动全量暂存或发布假设。

使用 `setup-matt-pocock-skills` 时先读取现有约定，落实 `issue-tracker.md`、`domain.md` 和 `triage-labels.md`。已有 backlog、词汇表或决定记录通过这些文件薄映射，其他技能沿同一入口工作。

## 记录真实状态与失败

| 状态 | 可以说明什么 |
|---|---|
| 已安装或已发现 | 找到技能、程序或说明，记录来源与能取得的版本信息 |
| 本轮可调用 | 当前会话暴露了相应入口 |
| 已配置 | 项目配置存在并指向明确目标 |
| 已验证 | 在指定环境与目标执行过检查，留下结果 |

这些状态不能互相推导。验证选择与任务相关、影响最小的操作。缺少技能时提示开发者安装命令；缺少认证、额度或环境时写明具体条件。可以满足同一结果的替代方式需说明差异，不能替代的验证保持开放。

## Herdr 与并行工作

Herdr 是通用偏好的终端与 worktree 组织入口，不属于某一个产品。使用前读开发者已安装的 Herdr 技能，核对它要求的上下文、目标和实际版本；当前技能要求 `HERDR_ENV=1` 时，只有满足条件才访问或控制会话。其他环境可以完成资料准备和独立工作，记录没有使用 Herdr，不绕过会话限制。

主代理之外默认最多两个活动子代理，研究、实现和审查共用额度；是否委派仍按当前用户、宿主与技能的授权。尚未约定其他模型策略时继承当前模型。每个并行实现任务使用独立 Git 工作副本，明确分支、目录、修改范围和集成负责人；只读研究可共享固定材料。终端分屏不是代码隔离，工作副本也不会自动隔离端口、数据库和测试输出。

任务完成后由主代理集成、检查组合结果，并按[开发环境](environments.md)收尾自有进程。项目层只填写允许的工作副本位置、具体验证环境和资源冲突；Herdr 不可用时如实记录组织入口，隔离和集成要求仍然适用。

项目填写入口见[工具适配模板](../templates/tool-adapters.md)与[技能使用细则模板](../templates/project-skill-policy.md)；初始化过程见[项目初始化](initialization.md)。
