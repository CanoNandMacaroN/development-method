# 开发环境与资源归属

本地和服务器说明工作在哪里进行；原生运行时和容器说明代码怎样运行。项目初始化应选择可完成真实验证的组合，并让下一位开发者能够重建所需环境。

## 在开始工作前确定这些位置

| 内容 | 要明确的事实 | 完成标准 |
|---|---|---|
| 源码与工作副本 | 当前仓库、分支、任务范围，其他正在进行的修改 | 能确定本轮改动属于哪里 |
| 工具与依赖 | 运行时版本、依赖锁定方式、安装入口 | 能按同一输入准备环境，不依赖未说明的全局状态 |
| 测试数据 | 样例来源、生成位置、允许修改的范围 | 能重复运行，测试不会改基准材料或日常数据 |
| 配置与凭据 | 配置模板、提供方式、可用权限 | 知道缺什么条件，不把真实凭据写进代码或日志 |
| 进程与端口 | 谁启动、用途、访问位置、结束方式 | 能识别本轮资源并只处理自己的资源 |
| 构建与报告 | 产物位置、生成方式、清理规则 | 能找到结果并确定其代码版本和验证范围 |

项目依赖和生成物保持独立。运行时按项目选择版本，已有安装与下载缓存可以复用；项目有更严格要求时使用其约束。共享缓存只用于复用下载材料，不把不同项目可修改的依赖目录混成一份，也不因此自动升级共享工具。

## 本地原生开发

需要真实桌面宿主、图形交互或本机集成的功能，保留原生验证入口。测试使用明确的测试资料与配置，先验证最小流程，不借日常账号和私人目录获得一个表面成功的结果。

记录宿主与运行时的实际版本、测试入口和必要条件。构建只产生包；把包放进测试宿主属于另一动作，两者的路径与副作用都能检查。普通构建不隐式部署到正在使用的环境。

## 在服务器开发

服务器也可以作为开发机器。明确当前连接的是哪个开发环境、源码在哪里、命令在哪个目录运行、哪些进程和数据属于本任务。连接标识与工作目录应来自实际读取的状态，不能根据终端标签猜测。

开发与正式服务默认分机。这个约定只规定开发工作的边界；本手册不建立正式服务的值守、告警和长期运维制度。访问或改变外部环境须处于已经明确的任务授权内。

断线或超时后先检查实际状态，再决定是否重试。某条创建或写入命令没收到回复，不代表它没有执行；重复运行前确认是否已产生结果，尤其是下载、提交、测试部署与文件写入。

## 容器开发

适合容器化的 Web 和后端项目，提供可重建的容器开发环境，让构建、测试和服务尽量在其中执行。环境声明与源码一起管理，并明确：哪些内容来自镜像，哪些目录来自宿主，哪些数据需要保留，端口怎样使用。

准备好容器不等于功能已经验证。仍需打通真实的最小流程，并核对容器内外的路径、文件权限、网络地址和时区等实际差异。涉及桌面宿主的行为回到原生环境验证。

将重建工具环境与清除持久数据分成不同入口。普通重建应能保留需要的开发数据；销毁数据前必须明确目标和影响。迁移到另一台机器时，环境声明、配置提供方式和数据准备步骤应足以复现，不依靠一份长期手工修改过的容器。

## 并行任务的环境

独立代码副本并不自动隔离端口、数据库、宿主配置或测试输出。分派实现任务时，同时确定这些资源是否共享；需要共享的资源指定使用顺序，不并发执行互相覆盖的测试。

Herdr 可以组织 worktree、终端与代理状态。任务中记录代码副本、分支和验证入口；窗格标识只用于当前运行定位，不成为产品规格或跨机器接续的永久身份。具体操作见[工具适配](tools-and-skills.md)。

## 收尾与重建

一批开发完成或暂停后，默认停止本轮持续开发服务，保留持久数据。供用户体验的预览按事先约定保留；一次进度消息不是结束信号。临时测试资源由创建者收尾，已有用户服务和其他任务的资源保持各自归属。

环境准备失败时，记录失败发生在哪一层、已经改变了什么、怎样恢复和下一步需要什么。缺条件的验证保持未完成，独立于该条件的工作可以继续。不要把重复尝试次数当作新的证据。
