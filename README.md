# AI 协作开发手册

规范版本：0.1.0，2026-10-12。用于一个人负责产品与关键决定、AI 承担主要工程工作的开发方式，也可按项目情况裁剪。目标是把一个想法变成能够验证、解释和继续迭代的实现，并留下换人、换会话后仍能接着工作的材料。

这是一份通用开发方法文档包。技能由开发者自行安装，包内只保留完整介绍、安装命令与配合项目开发的细则。通用层已经写好开发流程、技能和工具协作细则；项目层只绑定实际资料、环境、命令与有理由的例外。项目初始化通过已安装的技能配置项目文档入口，不复制技能源码，也不附带技能安装器。

## 直接用于一个项目

从[新项目启动入口](START-HERE.md)开始：解压到项目目录，复制其中的启动话术，围绕项目细节完成 Grill，由 AI 生成起步文档。已经确定的开发理念和工具配合方式直接继承。已有项目沿用现行权威做差异适配。

## 从哪里读

第一次阅读，先看[开发原则与完整流程](handbook/principles-and-flow.md)，再看[标签功能的完整示例](examples/labels-feature.md)。以后按正在做的工作进入，不必每次加载整本手册。

| 当前工作 | 阅读入口 | 读完应能做什么 |
|---|---|---|
| 理清需求、做方案 | [需求与设计](handbook/requirements-and-design.md) | 写出可判断对错的行为实例，找出数据和模块职责 |
| 开始写代码 | [实现方法](handbook/implementation.md) | 从真实入口追踪调用链，逐个行为实现，控制状态与副作用 |
| 写测试、修缺陷 | [测试与调试](handbook/testing-and-debugging.md) | 建立可信失败，选择适当验证层次，定位根因并做回归 |
| 审查、合并成果 | [审查与集成](handbook/review-and-integration.md) | 检查同一版本的需求与实现，核实发现，组合后再验证 |
| 使用本地、服务器或容器 | [开发环境](handbook/environments.md) | 确定代码、运行时、配置、数据、进程的归属及重建办法 |
| 更新文档、接续工作 | [上下文与文档](handbook/context-and-documents.md) | 找到现行事实，保存足够上下文，避免多份状态冲突 |
| 准备和使用技能工具 | [开发者安装说明](handbook/developer-setup.md)、[Matt 全集](handbook/matt-skills.md)、[使用分工](handbook/tools-and-skills.md) | 开发者准备能力，项目规定怎样配合开发 |
| 初始化或接管项目 | [启动入口](START-HERE.md)、[项目初始化](handbook/initialization.md) | 固定通用版本，生成项目适配，验证最小开发流程 |

[模板](templates/project-guide.md)帮助填写必需信息，不要求每个小改动都新增一整套文档。方法与材料来源见[来源与适配说明](SOURCES.md)。

## 通用内容怎样进入项目

通用包保存方法、示例和模板。项目固定采用其中一个版本，保存自己的目标、技术事实、命令、当前状态及有理由的例外。升级通用包时核对差异；日常开发不静默跟随全局技能文件或远端最新规则改变。

人读手册与代理入口引用同一套事实。代理入口负责告诉 AI 在什么情况下读取什么，不再复制一份长篇规范。原有项目采用差异适配：保留产品决定和真实实现，修正文档位置、权威和入口，不重新建仓或假装从零开始。

## 本版的验证范围

本版接受本地引用、内容一致性、可迁移性和独立阅读检查；示例是用于解释方法的假设任务，不是一次真实产品验收。初始化检查应验证项目文档之间的入口、权限、路径和真实开发流程，不将文件存在当作技能或工具已经运行。真实宿主、外部服务和 Herdr 会话的可用性要在实际使用环境分别核对。
